# فاز ۲.۱۶ — پایداری و آماده‌سازی ساخت خودکار اندروید

## هدف
کاهش مصرف حافظه در ویرایشگر عکس و فراهم‌کردن مسیر ساخت APK در GitHub Actions؛ بدون حذف قابلیت‌های فعلی یا تغییر رفتار خروجی اصلی.

## تغییرات
- پیش‌نمایش ویرایش عکس همچنان از تصویر کوچک‌شده‌ی `photoPrev` استفاده می‌کند و خروجی PNG/JPEG همچنان از `photoSrc` با وضوح اصلی ساخته می‌شود.
- رندرهای پیش‌نمایش قبلی پس از جایگزینی یا خروج از صفحه آزاد می‌شوند.
- اگر رندر پیش‌نمایش هنگام تغییر سریع تنظیمات لغو شود، bitmap حاصل پس از پایان پردازش آزاد می‌شود و به UI منقضی‌شده تحویل داده نمی‌شود.
- در `PhotoEdit.apply` بیت‌مپ‌های میانیِ حاصل از چرخش/قرینه/برش پس از مصرف آزاد می‌شوند؛ منبع اصلی دست‌نخورده می‌ماند.
- نسخه برنامه به `versionCode 26` و `versionName 1.0-r10.16` ارتقا یافت.
- workflow ساخت خودکار در `.github/workflows/android-build.yml` اضافه شد: Java 17، Gradle 8.7، Android SDK 34، اجرای unit test و ساخت APK آزمایشی؛ در صورت موفقیت APK به‌عنوان artifact ذخیره می‌شود.

## محدودیت‌ها و اعتبارسنجی
- در محیط فعلی Gradle و Android SDK در دسترس نبود؛ بنابراین workflow هنوز روی GitHub اجرا نشده و ساخت موفق APK تأیید نشده است.
- تغییرات Kotlin از نظر ساختاری بازبینی شدند، اما کامپایل Kotlin/Android و تست روی گوشی انجام نشده است.
- workflow در اولین push به شاخه‌ی `main` یا `master` یا با اجرای دستی از زبانه Actions اجرا خواهد شد. اگر build شکست بخورد، لاگ خطای واقعی باید بررسی و اصلاح شود.
- این فاز مدل آموزش‌دیده‌ی جدیدی اضافه نمی‌کند. تشخیص علمی همچنان وابسته به مدل‌های TFLite واردشده و دیتاست/وزن‌های واقعی است.

## خروجی مورد انتظار در GitHub
پس از اجرای موفق workflow، از مسیر Actions > Android build > Artifacts می‌توان `lightninglab-debug-apk` را دریافت کرد. این APK آزمایشی است، نه نسخه امضاشده برای انتشار فروشگاهی.
