# LightningLab r10.71 — ماندگاری بازبینی انسانی رخدادهای صاعقه

این نسخه یک مشکل واقعی r10.67–r10.70 را اصلاح می‌کند: برچسب تأیید/رد/نامشخص بازبین فقط تا وقتی تحلیل روی صفحه بود در حافظه باقی می‌ماند.

## پیاده‌سازی
- تصمیم‌های بازبین برای رخدادهای شناسایی‌شده در پوشهٔ خصوصی برنامه و به شکل JSON اتمیک ذخیره می‌شوند.
- نام فایل sidecar با SHA-256 از URI منبع ساخته می‌شود؛ مسیر یا نام فایل ویدئو به‌صورت متن خام در sidecar ثبت نمی‌شود. هیچ اتصال شبکه‌ای برای این قابلیت استفاده نمی‌شود.
- شناسهٔ موقت رخداد به‌عنوان کلید ماندگار استفاده نمی‌شود. کلید از زمان شروع، پایان و بهترین فریم رخداد ساخته می‌شود تا تصمیم به رخدادی اشتباه انتقال پیدا نکند.
- در تحلیل مجدد **همان URI**، تصمیم‌های موجود تنها برای رخدادهای دارای سه زمان کاملاً یکسان دوباره در رابط بازبین نمایش داده می‌شوند. تغییر خروجی detector/trim می‌تواند باعث شود تصمیم قبلی روی رخداد جدید اعمال نشود؛ این رفتار محافظه‌کارانه عمدی است.
- گزارش‌های CSV و JSON پیشین همچنان `human_review` را جدا از امتیاز heuristic/model نمایش می‌دهند.
- محدودیت ۵۰۰ تصمیم و ۱۰۰ کیلوبایت برای هر sidecar اعمال شده؛ دادهٔ خراب یا فرمت نامعتبر بازیابی نمی‌شود.
- رابط کاربری وضعیت ذخیره‌سازی را نشان می‌دهد. ذخیره با وقفهٔ کوتاه ۳۵۰ میلی‌ثانیه و روی IO انجام می‌شود تا لمس UI متوقف نشود.

## آزمون
- `LightningReviewSidecarTest`: کلید مستقل از ID، رد زمان غیرممکن، رد برچسب نامعتبر.
- تست‌های موجود ProjectCodec، VideoDraft و Photo Studio نباید تغییر کنند.
- پس از هر commit، تست JVM/Python و بیلد APK GitHub Actions باید موفق باشند.
- آزمون روی گوشی فیزیکی با ویدئوی واقعی، خروج اجباری برنامه و انتخاب فایل با URI متفاوت لازم است. بازبینی دقیق رخدادها به اندازه‌گیری علمی CG/IC یا انرژی صاعقه تبدیل نمی‌شود.

## مواردی که همچنان باید توسعه یابند
- مدلسازی واقعی/اعتبارسنجی‌شدهٔ صاعقه و ابرها روی دیتاست مستقل، تشخیص اطمینان مدل و سنجش calibration.
- cloud video motion با جبران حرکت دوربین؛ ROI حذف پیش‌زمینه/بازتاب خورشید.
- keyframe کامل و transitionهای حرفه‌ای ویدئو، RAW/DNG و پردازش tile-based عکس.
- تست UI instrumentation، دستگاه واقعی، باتری، مقایسه preview/export و تست پایداری طولانی‌مدت.
