# فاز ۲.۱۷ — یکپارچه‌سازی، پایداری حافظه و بیلد واحد

## تغییرات
- مسیر بیلد GitHub Actions به یک workflow واحد در `.github/workflows/build.yml` محدود شد.
- workflow اکنون فقط با بارگذاری `update.zip` یا اجرای دستی فعال می‌شود؛ اجرای مجدد ناشی از commit ربات از ساخت تکراری جلوگیری می‌کند.
- فایل به‌روزرسانی باید شامل سورس کامل پروژه اندروید باشد (از جمله `settings.gradle.kts`، `build.gradle.kts` و پوشه `app`). مسیرهای ناامن داخل ZIP رد می‌شوند.
- ساخت خودکار شامل Java 17، Gradle 8.7، Android SDK 34، اجرای تست‌های واحد و تولید APK آزمایشی است.
- در پیش‌پردازش مدل تشخیص جنس ابر و ویژگی‌های ساختاری، بیت‌مپ‌های موقت در تمام مسیرهای موفقیت و خطا آزاد می‌شوند؛ بیت‌مپ اصلی متعلق به UI دست‌نخورده می‌ماند.
- نسخه برنامه به `1.0-r10.17` و `versionCode 27` ارتقا یافت.
- رابط شیشه‌ای داشبورد، ویرایشگر عکس و ویرایشگر ویدئو و اتصال‌های فعلی آن‌ها حفظ شدند.

## محدودیت‌های مهم
- این فاز هیچ وزن مدل آموزش‌دیده‌ای تولید نمی‌کند. فایل‌های `.tflite` باید جداگانه با قراردادهای مستند آموزش داده و وارد برنامه شوند؛ بدون آن‌ها، تحلیل ابر به روش قانون‌محور و غیرقطعی برمی‌گردد.
- حذف پس‌زمینه با ML Kit به دریافت اولیه مدل از Google Play Services وابسته است؛ بنابراین این قابلیت در اولین استفاده تضمین‌شده‌ی کاملاً آفلاین نیست. سایر مسیرهای TFLite پس از واردکردن مدل روی دستگاه اجرا می‌شوند.
- محیط توسعه فعلی Gradle و Android SDK نصب‌شده ندارد؛ در نتیجه کامپایل APK و اجرای تست‌های اندروید در اینجا انجام نشده است. نتیجه نهایی فقط پس از اجرای workflow در GitHub مشخص می‌شود.
