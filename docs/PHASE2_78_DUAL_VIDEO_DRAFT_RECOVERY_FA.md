# A03 — نسخهٔ r10.78: دو نسل بازیابی خودکار پروژه ویدئو

## مسئله‌ای که اصلاح شد
در r10.77 فایل draft.json به شکل اتمیک ذخیره می‌شد؛ اما پس از انتشار فایل جدید، تصاویر مربوط به نسخه قبلی حذف می‌شدند. اگر JSON جدید بعداً معیوب می‌شد، دیگر مسیر fallback با یک مجموعه کامل فایل وجود نداشت.

## اصلاحات اجرایی
- فایل draft.previous.json یک نسخه اتمیک مستقل از آخرین snapshot معتبر قبلی است.
- پیش از انتشار draft.json جدید، snapshot فعلی در previous ذخیره می‌شود. اگر نوشتن previous شکست بخورد، فایل current دست‌نخورده باقی می‌ماند.
- پس از commit جدید، پاک‌سازی overlayها به‌جای آخرین manifest، اجتماع تصاویر ارجاع‌شده در current و previous را حفظ می‌کند.
- در read، ابتدا draft.json بررسی می‌شود؛ اگر خراب، غیرمعتبر یا فایل PNG مرتبط گم باشد، previous بررسی می‌شود.
- قواعد pure در VideoDraftRecoveryPolicy قرار گرفتند و تست‌هایی برای fallback، فایل مخدوش، PNG مفقود و retention نوشته شد.
- توکن نام‌گذاری overlay از SecureRandom و بررسی عدم تداخل نام استفاده می‌کند.
- delete دستی هر دو نسل و تصاویر را حذف می‌کند؛ **بازیابی پس از حذف صریح کاربر وعده داده نمی‌شود**.

## محدودیت‌های باقی‌مانده
- این تغییر بکاپ فایل ویدئوی اصلی نیست. media URI اگر مجوز یا فایلش از بین رفته باشد همچنان قابل بازیابی نیست.
- سلامت بایت‌به‌بایت PNGها بررسی نشده؛ preflight تصویر هنگام restore انجام می‌شود.
- قطع برق میان عملیات دیسک و پاک‌سازی فایل، ممکن است orphaned assets بی‌خطر ایجاد کند.
- دو نسخه در حافظه داخلی، storage بیشتری مصرف می‌کنند. برنامه نیاز به پنل مدیریت حجم و حذف فایل‌های بلااستفاده بلندمدت دارد.
- Android instrumentation تست process-death، پرشدن حافظه و قطع ناگهانی واقعی هنوز اجرا نشده است.

## کارهای بعدی A03
1. failpoint instrumentation در هر نقطه write و rollback، و شبیه‌سازی process death.
2. re-link رسانهٔ گم‌شده با SAF و persistable URI grants.
3. گزارش حجم و retention policy بر اساس بودجه cache.
4. نسخه‌بندی migration و export پروژه قابل انتقال بین دستگاه‌ها.
5. تست‌ها و بهینه‌سازی performance UI در گوشی واقعی.
